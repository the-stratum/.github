# Support

Thank you for using and taking an interest in STRATUM projects.

STRATUM is an independent engineering and creative collective working across software, developer tools, web applications, infrastructure, automation, and creative technology.

This document explains how to find project information, ask questions, report problems, and contact the STRATUM community.

## 1. Where to Get Help

Choose the support channel that best matches your question.

### GitHub Repositories

For project-specific questions, begin with the relevant repository.

- Read its README and available documentation.
- Check existing issues before creating a new one.
- Review the project's installation, configuration, and troubleshooting instructions.
- Check its releases and known limitations where available.

Explore STRATUM repositories:

https://github.com/the-stratum?tab=repositories

### GitHub Issues

For technical problems, reproducible bugs, and project-specific feature requests, use the Issues section of the relevant repository when issues are enabled.

Before opening an issue:

- Search for existing reports covering the same problem.
- Confirm that you are using a supported version, where specified.
- Provide enough information for maintainers to understand the problem.
- Keep one issue focused on one problem or proposal.

Issues should contain technical information relevant to the project and must not include credentials, private information, or sensitive security details.

### STRATUM Discord Community

Join the STRATUM Discord community for general questions, project discussions, and collaboration.

**Discord:** https://discord.gg/VhphZQuyhj

Use the appropriate available channel and provide enough context for other members to understand your question.

Please respect the community's Code of Conduct and avoid posting confidential information.

### Email

For general enquiries, collaboration requests, or matters that cannot reasonably be handled through public project channels, contact:

**stratum027@gmail.com**

Include the relevant project name and a clear description of your enquiry.

## 2. Reporting a Bug

When reporting a technical problem, provide as much of the following information as possible:

- Repository and project name.
- Software version or affected commit.
- Operating system and relevant environment details.
- Steps to reproduce the problem.
- Expected behaviour.
- Actual behaviour.
- Relevant error messages or logs.
- Screenshots or other supporting evidence, where useful.

A clear, reproducible report makes investigation easier.

Do not remove important error details, but redact secrets and personal information before sharing logs.

## 3. Requesting a Feature

Feature proposals should explain:

- The problem or limitation being addressed.
- The proposed functionality.
- Why the improvement would be useful.
- Relevant examples or references.
- Any important compatibility or usability considerations.

Feature requests are evaluated according to project scope, technical feasibility, maintainability, and available resources.

Submitting a proposal does not guarantee implementation.

## 4. Security Issues

**Do not report security vulnerabilities through public GitHub issues, pull requests, Discord messages, or other public channels.**

For suspected vulnerabilities, follow the instructions in our security policy:

https://github.com/the-stratum/.github/blob/main/SECURITY.md

Security reports should be submitted privately using an available GitHub private vulnerability reporting option or the designated email address described in that policy.

## 5. What STRATUM Support Covers

Support is focused on helping users understand and use STRATUM-maintained projects.

Depending on the project and available resources, this may include:

- Installation and configuration guidance.
- Help understanding documented functionality.
- Reproducing and investigating reported bugs.
- Clarification of project behaviour and limitations.
- Guidance on reporting issues and proposing improvements.
- General project and community enquiries.

Individual repositories may define additional support requirements and limitations.

## 6. What Support Does Not Guarantee

STRATUM does not guarantee:

- Immediate or continuous support.
- Fixed response or resolution times.
- Implementation of every feature request.
- Compatibility with unsupported environments.
- Troubleshooting for unrelated third-party products or services.
- Custom development or professional consulting for every enquiry.

Support availability depends on project maintainers, community participation, and available resources.

## 7. Before Requesting Help

To make support more effective:

- Read the relevant documentation first.
- Search for existing issues and solutions.
- Use a clear and descriptive title.
- Include relevant technical details.
- Avoid duplicate reports.
- Be respectful and patient when communicating with maintainers and community members.

Never share passwords, API keys, access tokens, private keys, recovery codes, or other confidential information when requesting help.
